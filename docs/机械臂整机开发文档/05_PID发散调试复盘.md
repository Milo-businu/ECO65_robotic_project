# PID 闭环发散：四轮调试完整复盘（面试素材）

> 场景：睿尔曼 ECO65-6FB + ROS2 Foxy + Gazebo，自研 PID 外环做正弦轨迹跟踪。

## 四、三个真问题的技术细节（面试会追问）

### 4.1 角度环绕（Angle Wrapping）

**现象**：连续旋转关节（本例 joint6，限位 ±2π）的位置反馈被归一化到 [−π, π]。真实角度 3.5 rad 时反馈报 −2.78（3.5 − 2π），误差瞬间变成 ~2π 量级。

**为什么误差会"≈π"**：归一化跳变产生的虚假误差落在 [0, 2π] 区间，其典型峰值特征接近 π。

**修复**（标准做法）：

```python
def wrap(a):
    """角度误差归一化到 [-π, π]"""
    return np.array([math.atan2(math.sin(x), math.cos(x)) for x in a])

e = wrap(q_des - q)      # 而不是直接 q_des - q
```

**效果**：joint6 RMS 从"拖垮全局"→ 0.043。

> **面试加分句**：这是机器人学的经典坑，凡是连续旋转关节（6 轴末端、全向轮）都要考虑，我在写第一版时就该想到——所以后来我把「角度归一化」写进了项目的编码规范。

### 4.2 wrap 的副作用：限位死锁

**现象**：J3/J4 被推到负限位（−2.79 / −3.10）后，真实误差 +3.3 **超过半圈**，wrap 把它折叠成 −2.95（选择"短路径"）。但短路径方向是**限位墙**——PID 持续往墙推，永远回不来。

**关键洞察**：
- 对**连续关节**，wrap 完全正确（转回去更近）
- 对**有限位关节**，"短路径"方向可能被墙堵死 → 死锁

**这也是为什么误差最大值的「天花板」精确停在 3.140 / 3.136**：那就是 wrap 的上界 π，是死锁的诊断指纹。

> **面试加分句**：修复一个 bug 引入了下一个 bug——所以我学会了「修完必须重新审视副作用」，这也是我坚持每轮都跑对照实验的原因。

### 4.3 控制器状态损坏（最隐蔽的一个）

**铁证**：发了「3 秒回零位」的 goal，但下一轮启动时的起始关节角**仍残留上次跑飞的位置**（不是全零）。

这说明：**不是我们的算法问题，是底层不再执行指令了**。事件链：

```
某次异常 goal → 控制器进入错误状态 → 后续所有 goal（含回零）被拒/夭折
  → PID 误差恒巨且随机 → 越调越乱 → 状态跨会话累积恶化
```

**验证与解决**：重启仿真（清状态）→ 立刻复测 → 起始完美零位、六关节均匀稳定。**确诊**。

> **面试加分句**：我一开始一直在调 Kp/Ki/Kd，全都无效。转折点是我意识到**应该先怀疑被控对象，再怀疑控制器**——如果执行机构根本不干活，再好的控制律也没用。这是那晚最重要的一课。

## 五、定量分析：用数学证明"剩余误差不是 bug"

重启后系统健康，但总体 RMS 仍为 0.270（各关节 ~0.11）。我没有继续瞎调，而是**先算它应该是多少**：

```
目标：正弦，幅度 A=0.12 rad，频率 f=0.25 Hz
最大角速度 = 2π·f·A = 2π × 0.25 × 0.12 ≈ 0.19 rad/s
控制周期 DT = 0.5 s
滞后误差 ≈ 角速度 × 滞后时间 = 0.19 × 0.5 ≈ 0.095 rad
```

**实测各关节 RMS ≈ 0.11 rad**——与预测 0.095 几乎吻合。

结论：**残余误差 = 控制频率太低造成的跟踪滞后，不是 bug**。解法明确：提高控制频率（DT 0.5 → 0.15），预期 RMS 降到 0.03 量级。

> **面试加分句**：调试的终点不是"跑通了"，而是"我能用公式解释每一个数字"。能定量预测误差，才说明真的理解了系统。

## 六、可迁移的调试方法论（最重要，面试官最爱听）

### 6.1 指纹法：让数字自己说话
不要只看"大/小"，要看**特征数值**：
- 误差 ≈ π → 角度环绕
- 误差卡在 π 天花板 → wrap 死锁
- 误差接近满量程/限位 → 正反馈跑飞
- 误差均匀但偏大 → 滞后/带宽不足（可定量）

### 6.2 二分法：每轮实验砍掉一半假设
- 「幅度设为 0」→ 区分「保持不住」还是「跟踪不了」
- 「改轨迹形式（单点→两点）」→ 区分「目标表达」还是「执行机制」
- 「降频降增益」→ 区分「增益过大」还是「执行滞后」

### 6.3 先怀疑被控对象，再怀疑控制器
执行机构可能：不执行 / 执行错方向 / 状态损坏 / 反馈失真。**先确认它在干活**，再调你的算法。

### 6.4 定量验证替代"看起来好了"
预测值 vs 实测值吻合 → 理解正确；不吻合 → 还有未知因素。

### 6.5 诚实地区分"证实"与"推测"
那晚我在每一轮都明确写了：这条是**数据证实的**，那条是**待验证的假设**，并给出验证方法。**不拿猜测冒充结论**——这是工程素养，也是面试里最难伪装的东西。
