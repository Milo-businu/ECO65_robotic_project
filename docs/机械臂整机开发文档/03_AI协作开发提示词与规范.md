# AI 协作开发提示词与规范（ECO65 六维力版 + Foxy + VLA 版）

> 目标：让 AI 帮你把 ECO65 六维力版智能抓取程序写得**模块化、可运行、可修改、可读性强、注释好**。
> 核心心法一句话：**别让 AI 一次写一整套，而是「先定规矩 → 接口先行 → 一次只交一个模块 → 强制验收」。**

---

## 一、五条铁律（指挥 AI 的总原则）

1. **接口先行**：先定义消息/服务/话题/函数签名，再写实现。接口是合同，实现是细节。
2. **一次一个模块**：一个 prompt 只让 AI 做一件事。贪多必烂。
3. **可运行优先**：每个模块必须带一个能直接跑的最小示例 + 单元测试，跑不通不算完成。
4. **注释即文档**：每个函数写「输入/输出/单位/物理含义」，注释要能被别人读懂。
5. **小步验收**：AI 交代码后，你必须自己跑一遍测试，跑不通就让它改。

---

## 二、全局规范（CODING_STANDARD.md，先给 AI 读）

```markdown
# CODING_STANDARD.md —— 本项目编码规范（AI 必须遵守）

## 1. 语言与版本（锁定）
- 系统：Ubuntu 20.04；ROS2：Foxy（官方 ros2_rm_robot 只支持 Foxy，勿升级）
- 机器人侧节点：Python 3.8（Foxy 默认）/ C++17
- OpenPI 推理：独立 conda/uv 环境，Python 3.9+，PyTorch + CUDA，与 ROS 解耦
- 构建：colcon（机器人侧）；测试：pytest（Python）/ gtest（C++）

## 2. 命名规范
- 文件/函数/变量：snake_case（如 compute_jacobian）
- 类：PascalCase（如 VlaBridge）
- 常量：kPascalCase；成员变量加尾下划线（如 q_）
- 不用拼音、不用缩写（公认缩写除外：FK/IK/J/PID/VLA）

## 3. 注释规范（非常重要）
- 每个函数顶部写 docstring，含 5 项：
  ① 干什么（一句话）
  ② 输入参数（含单位）
  ③ 返回值（含单位）
  ④ 核心公式/算法出处
  ⑤ 使用示例（可选）
- 每个物理量第一次出现写一行大白话。
- 复杂公式旁写一行「这公式在算什么」。
- 禁止无意义注释（如 `# 定义变量 a`）。

## 4. 单位与坐标系（全项目统一）
- 长度：米；角度：弧度；时间：秒
- 角速度 rad/s；力矩 N·m
- 齐次变换 4×4：旋转 3×3 在前，平移第 4 列
- 坐标系（2026-10-19 实测于官方 rm_description，写代码照抄这套名字）：
  **world → baselink → Link1 → Link2 → Link3 → Link4 → Link5 → Link6 → gripper**
  - 根帧 = `baselink`（**不是** base_link，无下划线）
  - 连杆 = `Link1`~`Link6`（**不是** link_1；L 大写、无下划线）
  - **没有 tool0**，末端 = `Link6`，夹爪装在 Link6 上
  - 关节名 = `joint1`~`joint6`

## 5. 机械臂硬参数（ECO65 六维力版，写死进配置文件，不散落在代码里）
- 关节限位（弧度）：J1 ±3.106，J2 −3.106~2.356，J3 −2.792~2.53，
  J4 ±3.106，J5 ±3.106，J6 ±6.28
- 最大速度（URDF 实测）：**J1~J3 = 3.14 rad/s（180°/s），J4~J5 = 3.92 rad/s（225°/s）**，J6 待确认（按说明书 225°/s = 3.92）
- 力矩上限：手册 J1~2 = 60 N·m、J3 = 30 N·m、J4~6 = 10 N·m；但 URDF 的 `effort` 统一写 100 N·m，**安全限速以 URDF 为准（更保守）**
- 六维力传感器：量程 200 N / 7 N·m，精度 ±0.5% FS（力控/拖动示教/夹持力反馈用）
- MDH 参数：d1=162.5mm，a2=−86mm，a3=260mm，a4=240mm，d4=−58.9mm，d5=110mm，d6=96.7mm（6FB）

## 6. 错误处理
- 输入越界、矩阵奇异、IK 无解：返回错误码或抛异常，不静默失败。
- 求逆前必须检查奇异性，用阻尼最小二乘兜底。
- 关节指令超限（限位/速度）时拒绝执行并告警。

## 7. 依赖
- 只允许：Eigen3、标准库、ROS2 官方库、OpenCV。不自己造矩阵轮子。
- 新增第三方库必须先说明理由。

## 8. 目录结构
- 一个包一个功能；每包内必须有 README.md + 单元测试 + example 最小示例。
```

## 三、VLA 专项约定（新增强制，指挥 AI 写 VLA 相关代码时必读）

```markdown
# VLA_CONTRACT.md —— VLA 接口契约（AI 必须遵守）

## 1. 动作空间（第一版统一）
- 采用「末端位姿增量 + 夹爪」：[Δx Δy Δz Δroll Δpitch Δyaw gripper]
- 单位：位置增量米、姿态增量弧度、gripper 用 0~1（0 闭合 1 张开，或相反，全项目统一）
- 理由：末端位姿增量不绑定具体机械臂，换臂只改底层 IK，不改模型

## 2. 观测接口（喂给模型的数据）
observation = { image, robot_state, instruction }
- image：相机图像（或多视角图像列表）
- robot_state：关节角 q[6] + 末端位姿 + 夹爪状态
- instruction：自然语言指令（字符串）

## 3. ROS 话题契约（与 vla_bridge 对齐）
- /vla/instruction   std_msgs/String
- /vla/image         sensor_msgs/Image（或自定义多视角）
- /vla/robot_state   自定义：float64[6] joint_pos + geometry_msgs/Pose + gripper
- /vla/action        自定义：float64[6] delta_pose + float64 gripper

## 4. 数据与归一化
- 状态/动作都要归一化（存 mean/std 统计量），训练与推理用同一份
- 一条示教轨迹 = 时间对齐的图像帧 + 关节角/末端位姿 + 夹爪状态 + 指令 + 标签
- 多模态时间戳必须对齐，不同步的数据要丢弃

## 5. 环境解耦
- OpenPI 推理跑在独立 conda/uv 环境，Python 依赖绝不污染 ROS 环境
- ROS 侧只通过 vla_bridge 的话题/服务与推理进程通信
```

## 五、示例任务卡：PID 底层控制（ECO65）

```markdown
【模块任务卡：arm_control —— 关节 PID + 末端位姿增量跟踪】

一、目标
实现 ECO65 每个关节的 PID 控制器 + 重力前馈，能跟踪关节轨迹，
并把「末端位姿增量 Δpose」转成关节指令执行（供 VLA 动作落地）。

二、输入 / 输出接口
- 输入：目标关节角 q_des / 目标末端位姿增量 Δpose（话题）
- 反馈：实际关节角、角速度（订阅 /joint_states）
- 输出：关节指令（发布给 rm_driver）
- 参数：Kp、Ki、Kd、重力补偿开关（ROS2 parameter）

三、依赖
- 官方 rm_ros_interfaces（关节指令消息）
- 官方 rm_description（URDF，用于 FK/IK/重力）

四、约定
- 单位：弧度、rad/s、N·m、秒
- PID：tau = Kp·e + Ki·∫e dt + Kd·de/dt + g(q)，积分项加抗积分饱和
- 末端位姿增量 → IK → 关节目标 → PID

五、核心算法
- 关节空间 PID（每关节独立）
- 重力前馈（用 URDF 质量/惯量算 g(q)）
- 安全：用 ECO65 关节限位表 + 速度上限做指令裁剪

六、验收标准
1. 单元测试：阶跃响应无静差（< 0.001 rad）
2. 正弦轨迹跟踪 RMS < 0.01 rad
3. 末端位姿增量能正确转成关节指令并到点
4. 关节指令永不超过 ECO65 限位/速度上限
5. 附 example_pid.py，Gazebo 里跑通轨迹跟踪

七、注释要求
每个 Kp/Ki/Kd 写清物理含义；说明抗积分饱和在哪、为什么

八、禁止事项
- 不写硬件驱动（官方 rm_driver 已提供）
- PID 参数、关节限位不硬编码，走参数/配置文件
- 不做轨迹生成（那是规划/模型的事）
```

## 六、示例任务卡：vla_bridge（核心）

```markdown
【模块任务卡：vla_bridge —— OpenPI ↔ ROS 接口】

一、目标
把 ROS 数据（指令、图像、状态）喂给 OpenPI 推理进程，把推理结果
转成 ROS 动作话题，实现 VLA 决策与 ROS 控制的桥梁。

二、输入 / 输出接口
- 订阅：/vla/instruction、/vla/image、/vla/robot_state
- 发布：/vla/action
- 与推理进程通信：进程间（如 socket / 共享内存 / 服务），不污染 ROS 环境

三、依赖
- 官方 rm_ros_interfaces（robot_state 来源）
- arm_perception（image 来源）
- 不直接 import OpenPI 的 PyTorch 依赖（保持解耦）

四、约定
- 遵守 VLA_CONTRACT.md：动作空间 = [Δx Δy Δz Δroll Δpitch Δyaw gripper]
- 消息字段名、单位、归一化方式与 VLA_CONTRACT.md 完全一致

五、核心算法
- 订阅→打包 observation→请求推理→解析 action→发布
- 时间同步：图像/状态/指令用最近时间戳对齐
- 动作超时/异常时进入安全停止

六、验收标准
1. 用「假推理进程」（回显固定动作）跑通全链路
2. 四个 /vla/* 话题收发正常，字段与契约一致
3. 动作超时能安全停止
4. 附 example_bridge.py + 假推理脚本，能直接跑通

七、注释要求
每个话题字段写清含义和单位；说明时间同步策略

八、禁止事项
- 不把 PyTorch/OpenPI 依赖装进 ROS 环境
- 不在 bridge 里写模型逻辑（模型在独立进程）
- 不硬编码话题名，走参数
```

六、验收标准

七、注释要求
每个字段写清含义、单位、来源

八、禁止事项

- 数据格式不自定义，遵守 VLA_CONTRACT.md

## 十、AI 写代码最容易犯的坑（提前告诉它避开）

1. **单位混用**：弧度/度、米/毫米混着来 → 规范强制统一。
2. **硬编码参数**：把 ECO65 关节限位、DH、PID 写死在代码里 → 全部走配置文件。
3. **求逆不防奇异**：直接 `inv(J)` 卡死就崩 → 强制阻尼最小二乘。
4. **VLA 与 ROS 环境污染**：把 PyTorch 装进 ROS 环境 → 强制独立 conda + bridge 解耦。
5. **动作空间不一致**：训练用关节角、推理用位姿增量，对不上 → 用 VLA_CONTRACT.md 锁定。
6. **一次写太多**：一个 prompt 塞 5 个模块 → 一次一个模块。

验收：我能在本地 colcon build 全通过，且 ros2 launch rm_bringup rm_eco65_gazebo.launch.py 能启动仿真。
