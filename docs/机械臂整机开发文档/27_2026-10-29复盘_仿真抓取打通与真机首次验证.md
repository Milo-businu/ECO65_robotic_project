## 三、三个关键判断

### 3.1 停止"死磕插件"，转向真机（上午的方向审视）

我给出的判断是：**大方向对，但当前环节已进入收益递减区**。

理由：`gazebo_grasp_fix` 模拟的是**真机上不存在的困难**——真机夹 60g 方块靠摩擦就够了
（理论需 0.20 N/侧，夹爪能力远超），插件改的 4 处源码真机一条都用不到。

并纠正了验收标准：应该验证**规划的抓取位姿是否满足力封闭**（纯几何判据，不依赖仿真器、
能带到真机），而不是"物理引擎把方块抬起来"。

> 这个判断今天被验证了：真正让闭环稳定下来的，是**几何对齐 + 参数机理**，不是继续调插件。

### 3.2 "固化"必须检查依赖链

把 `/tmp` 的脚本移进 Git 时，我只移了脚本本身，**没查它 import 了什么**。
结果真机上直接 `ModuleNotFoundError: No module named 'grasp_v3'`——
那个 18KB 的依赖文件**从来没进过仓库**，云服务器能跑纯属临时文件还在。

### 3.3 仓库里的资源文件不等于"最新的"

同步时发现仓库里两份文件是旧版：
- `models/target_box/model.sdf`：8cm、无质量、自带 x 偏移（云服务器实际用的是 4cm、0.06kg）
- `gz_demo_common.py`：缺 `GZ_WORLD` 支持

**不能默认仓库里的就是对的**——同步时要 diff 关键资源。

## 五、方法论沉淀（3 条通用）

### ① 涉及轴向/姿态的改动，先实测再动手

我以为"末端旋转轴是竖直的"，实测零位 FK 发现**是水平的**（`[0,1,0]`）。
**几何直觉经常错**，改之前先算 FK 打印各轴方向。

### ② 给坐标系加旋转后，全局搜"隐式同姿态约定"

向量直接相加（`CAM_OFF + p_body`）、直接复用父系旋转矩阵——这类代码
**不报错、只给错结果**，是最难查的一类 bug。

### ③ 对坐标变换写离线数值验证

构造一个已知点，检查算出来对不对（新公式 `[0.05,0,0.43]` ✅ vs 旧公式 `[0.35,0,0.13]` ❌）。
**不要只在仿真里看结果**——仿真里干扰太多，定位慢。
