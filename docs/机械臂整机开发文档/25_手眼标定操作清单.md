# 25｜手眼标定操作清单（Eye-in-Hand，照着做）

> 适用：相机 **D435i** 装在末端法兰，标定板固定在桌面
> 目标：求出 `X = T_flange←camera`（相机长在法兰的哪个位置）
> 前置：相机已装好能出流（见 `24_RealSense_D435i_真机安装方案.md`）
> 编写时间：2026-10-29

---

## 零、为什么这一步非做不可

仿真里相机的外参是**我们写死的精确值**，所以感知直接就准。
真机上没人告诉你相机到底装歪了多少——**手眼标定就是把这个"装歪了多少"测出来**。

不做这一步，后面所有感知都是错的。

---

## 一、准备标定板（打印前先看）

- **类型**：棋盘格（比 ArUco 依赖少，OpenCV 自带）
- **规格**：内角点 **9 × 6**（也就是 10×7 个格子），单个方格 **25 mm**
- **打印注意**：
  - 用激光打印机，别用喷墨（边缘会晕）
  - 打印后**必须用尺子实量**方格边长，以实测值为准（打印常有几毫米误差）
  - 贴在硬平板上（亚克力/厚纸板），**不能翘边、不能反光**
  - 四周留 ≥2cm 白边（OpenCV 找角点需要）

> ⚠️ 方格边长填错是新手最常见的错误，**直接影响标定尺度的准确性**。

---

## 二、固定标定板

- 平放在桌面上，**固定死**（用胶带/夹具），整个采集过程不能动
- 放在机械臂容易看到的位置，且**工作区域内**（约 0.3~0.6 m）
- 保证从多个角度都能完整拍到

## 四、采集数据（真机上做）

### 4.1 装依赖

```bash
pip3 install numpy
sudo apt install -y python3-opencv ros-foxy-tf2-ros
```

### 4.2 跑采集脚本

```bash
python3 collect_handeye.py --cols 9 --rows 6 --square 0.025 \
        --out ~/handeye_samples.json
```

（把 `--square` 改成你**实量**的方格边长，单位米）

### 4.3 操作方式（半自动，人在回路）

```
把机械臂移到一个位姿 → 确认棋盘格完整入镜 → 回终端按回车 → 自动记录
重复 15~20 次 → 输入 q 回车 → 保存
```

### 4.4 ⚠️ 姿态多样性 —— 标定成败的关键

这是**最容易犯的错误**，必须看懂：

手眼标定的方程是 `A X = X B`，其中 `A` 是两个位姿之间法兰的**旋转差**。
**如果你只平移不旋转，`A` 的旋转部分就是单位矩阵，方程退化，旋转解不出来。**

具体怎么做：

| 要求 | 量化指标 |
|---|---|
| 位姿之间要有明显**旋转** | 相邻位姿姿态差 **> 15°**（越大越好） |
| 俯仰/偏航都要覆盖 | 别只绕一个轴转 |
| 标定板在画面中的位置要变 | 覆盖画面中心 + 四角 |
| 距离也要有变化 | 别总在固定距离 |
| 数量 | 至少 15 组，推荐 **20 组** |

**一个可行的采集套路**：
绕着标定板走一个"半球面"——先正上方俯视，再逐渐倾斜到侧面 45°，每个高度转 4 个方位角。

## 五、求解

```bash
python3 handeye_calib.py --input ~/handeye_samples.json --pairs all
```

输出就是 `X = T_flange←camera`，包含旋转和平移。

**看残差判断质量**（经验阈值）：

| 残差 | 判断 |
|---|---|
| 旋转 < 0.1° 且 平移 < 1 mm | 优秀 |
| 旋转 < 0.5° 且 平移 < 3 mm | 可用 |
| 旋转 > 1° 或 平移 > 5 mm | **重采**（多半是姿态不够多样，或标定板动了） |

## 六、验证（两层，第二层才作数）

### 6.1 数值验证（残差）

就是第五节看到的残差，只证明"数据自洽"。

### 6.2 实测验证（这才是真的）

**方法**：放一个已知位置的方块（比如用尺子量出它在基座系的坐标），
让机械臂走过去看它，比较"感知位置"和"尺子量出来的位置"。

| 偏差 | 判断 |
|---|---|
| < 3 mm | 标定合格 |
| 3~10 mm | 勉强能用，建议重采 |
| > 10 mm | 标定失败，检查：方格边长是否填对 / 标定板是否动过 / 姿态是否够多样 |

> 这一步的意义：残差小不代表标定对（可能只是数据自洽但系统性地错），
> **只有拿真值对过才算数**。

## 七、应用：把 X 发布成 TF

标定完要把结果用起来。在 launch 里发**静态**变换：

```python
Node(
    package='tf2_ros',
    executable='static_transform_publisher',
    arguments=['x','y','z','yaw','pitch','roll',   # 用标定得到的 X
               'flange', 'd435i_link'],
)
```

⚠️ **两个坑**：

1. **父系必须是 `flange`，子系是 `d435i_link`，不能发到 `optical_frame`**
   —— 否则会和 realsense 驱动自己发的那条边形成**双父冲突**。
2. `static_transform_publisher` 的旋转参数顺序是 **`yaw pitch roll`**（不是 roll pitch yaw！），
   从四元数转换时别搞反。

运行时坐标换算（每次现算，别缓存）：

```
p_base = T_base←flange(当前时刻) · X · p_camera
```

第一项随时间变化，**必须每次查 TF**，不能缓存。

## 八、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 脚本报"没找到棋盘格" | 行列数填错（填的是内角点数，不是格子数）/ 反光 / 没完整入镜 |
| TF 读取失败 | 机械臂没启动 / frame 名不对。用 `ros2 run tf2_ros tf2_echo base_link flange` 确认 |
| 残差很大 | 姿态不够多样；或标定板被碰动过（**一定要固定死**） |
| 残差小但实测偏很多 | 方格边长填错（尺度会整体错）/ 相机内参不对 |
| `solvePnP` 失败 | 内参没收到。确认 `/camera/color/camera_info` 有数据 |
| 缺少 scipy | 本脚本已改为**不依赖 scipy**，只依赖 numpy + cv2 + rclpy |
