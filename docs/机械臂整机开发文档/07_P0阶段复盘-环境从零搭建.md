## 4. 踩过的坑（现象 → 指纹 → 根因 → 解决）

| # | 现象 | 关键指纹 | 根因 | 解决 |
|---|------|---------|------|------|
| 1 | `ros2_install.sh` 报 404 | 清华镜像站路径找不到 | 本地 apt 索引过期，清单里记的还是旧版本包 | `sudo apt update` 重试；仍失败则换**腾讯云内网镜像**（`mirrors.cloud.tencent.com/ros2/ubuntu`）+ 官方 ros.key |
| 2 | launch 加载失败退出 | `No module named 'xacro'` | 缺 URDF 模板转纯 URDF 的"翻译器" | `apt install ros-foxy-xacro ros-foxy-gazebo-ros-pkgs ros-foxy-joint-state-publisher` |
| 3 | Gazebo 起了但机器人不动 | `controller_manager not found` + 插件加载失败 | 缺 ros2_control 控制框架三件套 | `apt install ros-foxy-gazebo-ros2-control ros-foxy-ros2-control ros-foxy-ros2-controllers` |
| 4 | `ros2 --version` 报错 | `unrecognized arguments` | **Foxy 的 ros2 CLI 根本没有 --version 参数** | 改用 `echo $ROS_VERSION` 或 `ros2 --help` |
| 5 | 端口被占 / 实体已存在 | `Address already in use`、`Entity already exists` | 上一次仿真进程残留 | `killall -9 gzserver gzclient` |

> 排错心法：**报错里的"文件名/数值/时间戳"就是指纹**——404 指向索引过期、`controller_manager not found` 指向缺失包。不猜，按指纹定位。

## 5. 技术要点（小白版）

- **ROS2 Foxy 为什么绑死 Ubuntu 20.04**：ROS 每个发行版只针对特定 Ubuntu 版本做二进制适配，Foxy ↔ 20.04 是一对一关系，所以选系统不是随意的。
- **URDF / xacro 是什么**：URDF 是用 XML 写的"机器人说明书"（有哪些杆件、关节在哪、能转多少度）；xacro 是它的模板语言，能带参数和宏，运行时再展开成纯 URDF。
- **ros2_control 是什么**：一套标准的"控制器框架"——机械臂本体只暴露"关节"接口，控制器负责把它们驱动起来并对外提供统一话题/动作。官方包依赖它，缺了就跑不起来。
- **colcon 为什么要先编 `rm_ros_interfaces`**：自定义消息接口要先生成，其他包才能引用它。

## 6. 面试怎么讲

### 30 秒电梯陈述（可背）

> "我在云服务器上从零搭了一套 ROS2 机械臂仿真环境。难点不在安装本身，而在于**这台服务器有使用期限**——所以我第一天就把 Git 仓库和 `setup_system.sh` 一键重建脚本立起来，把踩过的三个坑（源过期 404、缺 xacro、缺 ros2_control 框架）全部固化进脚本。最后 21 个包一次编译通过、Gazebo 里关节数据跑起来，而这整套环境在任何一台 Ubuntu 20.04 上一条命令就能重建。"

### STAR 结构

- **S（情境）**：服务器按天计费、到期销毁；手上只有一台没装任何软件的 Mac。
- **T（任务）**：搭起 ROS2 Foxy + 睿尔曼官方包 + Gazebo 仿真，且必须可移植。
- **A（行动）**：浏览器网页终端登录（Mac 零安装）→ 先建 Git 保险箱 → 遇 404 换内网镜像 → 逐个补齐缺失依赖 → 把全过程写成幂等脚本。
- **R（结果）**：21 个包 0 失败；`setup_system.sh` 可一键重建；三个坑全部记录在案。

### 高频追问

| 追问 | 回答要点 |
|------|---------|
| 为什么不直接在 Mac 上装 ROS2？ | ROS2 Foxy 官方不支持 macOS，Apple Silicon 无适配；Mac 只能当"前端"。 |
| 服务器到期了怎么办？ | 三样资产分离：代码+配置进 Git、环境脚本进 `env/`、数据与模型用下载脚本记录来源。机器是临时借的，资产是自己的。 |
| `setup_system.sh` 怎么保证可重复执行？ | 每步做存在性判断（`grep -q ... ~/.bashrc`、`if [ ! -d ]`），重复跑不会产生副作用。 |
| 装 CUDA Toolkit 了吗？ | 没有。PyTorch 安装包自带 CUDA 运行时，只装 NVIDIA 驱动即可——省半小时。 |

## 7. 可迁移方法论

1. **机器是临时的，资产是自己的**——第一天就立 Git，而不是等"做完再说"。
2. **安装过程即脚本**——每解决一个坑，立刻固化进脚本，坑只踩一次。
3. **验收要可观测**——不看"跑完没报错"，看"关节数据有没有在滚动"。
4. **报错看指纹不看情绪**——数值、文件名、时间戳里藏着根因。
