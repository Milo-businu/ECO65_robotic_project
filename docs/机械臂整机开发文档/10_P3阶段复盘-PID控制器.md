| ① 只 P | 0.256（目标 0.3 只到 0.04） | 重力持续下拉，P 需要误差才出力 |

## 4. 四轮调试证据链（本阶段的核心资产）

```
首跑发散 RMS 1.068、最大 3.197
  │
  ├─ 指纹：3.197 ≈ π → 假设：角度环绕（joint6 是连续旋转关节）
  │  └─ 实验：误差 wrap 到 [-π,π] → RMS 0.419，joint6 归位 0.043 ✅
  │
  ├─ 仍跑飞：J2/J3/J4（承重链）
  │  └─ 指纹：误差卡在 π 截断值（3.140/3.136）+ 起始角逐次恶化
  │     （−0.08 → −0.36 → −0.84 → −1.56）→ 机制：wrap 死锁在限位墙
  │
  ├─ 换两点轨迹、降频降增益 → 都无效
  │  └─ 决定性线索：**回零命令发出后关节角依然残留** → 控制器不再执行 goal
  │
  └─ 重启仿真 → 0.270，六关节齐步走 → 确诊"控制器状态损坏"（官方控制器偶发问题）
```

| 修掉/锁定的问题 | 性质 |
|----------------|------|
| 角度环绕（joint6 连续关节） | **真 bug，已修**（wrap） |
| 控制器状态损坏 | **环境问题，无法从外环根治** → 用看门狗兜底 |
| wrap 死锁在限位 | **机制已锁定**（有限位关节被推到墙后 wrap 选短路径方向） |
| 残余 0.058 误差 | **定量归因**：action 通道架构性延迟（相位超前实验否决了滞后模型） |

| # | 现象 | 指纹 | 根因 | 对策 |
|---|------|------|------|------|
| 1 | I 项消不掉静差 | 误差稳定在 0.101 | 积分限幅 5 N·m < 重力矩 5.7 N·m | 抗饱和上限须大于最大扰动 |
| 2 | 误差突现 ≈π | 3.197 | 连续旋转关节反馈环绕 | 误差 wrap 到 [-π,π] |

## 6. 面试怎么讲

### 30 秒电梯陈述

> "六关节 PID 闭环首跑直接发散——RMS 1.07 rad，而轨迹幅度只有 0.12。我没有乱调参数，而是先找指纹：最大误差 3.197 约等于 π，这是连续旋转关节角度环绕的典型特征，加 wrap 后 RMS 降到 0.42、问题关节归位。剩下的跑飞又暴露两个机制：wrap 会把关节锁死在限位墙上，以及**回零命令都不执行**——最后确诊是底层控制器状态损坏，重启即愈。整个过程四轮，修掉两个真 bug、锁定一个机制，残余误差用数学归因到通信通道延迟，并加了看门狗做兜底。"

### 能力映射

| 能力 | 体现 |
|------|------|
| 读数据能力 | 从 3.197≈π、起始角恶化链里读出物理含义 |
| 二分实验 | 用"保持实验""保守模式"把故障空间砍半 |
| 懂数学 | 用增益函数 g(σ)=σ/(σ²+λ²) 判定阻尼行为 |
| 系统观 | 区分"算法 bug"与"底层环境故障"，后者用看门狗兜底而非硬调 |
| **诚实** | 相位超前补偿假设被实验否决后主动更正 |
| 产品化思维 | 看门狗 + 自动回零 + 分关节报告，而不是"重启大法" |

### 高频追问

| 追问 | 回答要点 |
|------|---------|
| 为什么 RMS 0.058 也算验收？ | 方案定的是 0.01，差距来自 action 通道的架构性延迟（已用实验定量归因，相位超前补偿无效可证），**带备注验收比假装达标更专业**；改进路径是换话题直发。 |
| 看门狗为什么不直接修根因？ | 根因在官方控制器内部，从外环无法根治；工程上是"检测 + 安全停止"，这是产品化思维。 |
| 阻尼系数怎么选？ | 看增益曲线：λ 大→保守、λ 小→快但奇异处危险；本项目 λ=1e-3 配合每步 ≤0.15 rad 裁剪。 |
| 会不会是参数没调好？ | 用对照实验排除：降频降增益、换轨迹形式都无效，而重启立刻恢复 → 不是参数问题。 |

## 7. 可迁移方法论

1. **先找指纹，再谈假设**——数值里藏着物理含义（π、起始角漂移）。
2. **用实验砍故障空间**——保持实验/保守模式/重启对照，每次砍一半。
3. **区分"算法错"与"环境病"**——前者修代码，后者做兜底。
4. **兜底机制是产品化标志**——能检测、能安全停止，比"重启解决"高一档。
5. **带备注的验收**——说清差距与归因，比假装达标更专业。
