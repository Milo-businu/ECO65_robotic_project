# P0–P6 分步实施手册（可移植版 · 从零开始）

> 目标：从「两台空机器」开始，一步步做到 Phase 6，并且**环境能一键搬走**。
> 核心约束：腾讯云 HAI 有使用期限 → 所有资产必须「随时可带走」。
> 起点假设：Mac 什么都没装，云服务器什么都没装。
> 配套文档：02 方案（架构与实参）、03 提示词规范（AI 协作规矩）。

## 0. 从零开始：Mac 与服务器的第一次配置

### 0.1 好消息：Mac 现在什么都不用装

起步阶段**不需要**在 Mac 上装任何软件。腾讯云自带「网页终端」，用浏览器就能登录服务器敲命令。

**不用装**：不用装虚拟机、不用装 VS Code、不用装 SSH 客户端、不用装 Foxglove。

> 什么时候才需要装 Mac 端软件？等到你想舒服地写代码（VS Code）或看 3D 画面（Foxglove）时再说，见 0.5 节。现在先别分心。

### 0.2 第一次登录服务器（3 分钟）

1. 浏览器打开腾讯云控制台，进入你的 HAI 实例
2. 点「终端连接」（就是 OrcaTerm，你之前截图那个窗口）
3. 照这个填：

| 项目 | 填什么 |
|------|-------|
| 连接协议 | **终端连接 (SSH)** |
| 连接端口 | 22（默认） |
| 用户名 | `ubuntu` |
| 验证方式 | **密码验证** |
| 密码 | 下拉选「托管密码」，或填你创建时设的密码 |

4. 点「登录」→ 出现**黑色命令行窗口** = 你已经站在服务器里了

> 这个黑窗口就是服务器的「键盘和屏幕」。后面所有命令都在这里敲。
> 复制粘贴：Mac 上 `⌘C` / `⌘V` 通常可以直接用；不行就用右键菜单。

### 0.3 服务器首次初始化（整段复制，一次粘贴）

登录成功后，**把下面整段复制粘贴**进去回车：

```bash
# ① 更新软件源（第一次会比较慢，等它跑完）
sudo apt update && sudo apt upgrade -y

# ② 装常用小工具
sudo apt install -y git vim curl wget htop unzip

# ③ 配 Git 身份（把引号里换成你自己的，以后提交代码会署名）
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"

# ④ 建工作目录（后面所有东西都放这里）
mkdir -p ~/robot_vla_ws/src ~/robot_vla_ws/env

# ⑤ 让 ROS 环境以后自动加载（先写上，装完 ROS 才生效）
echo "source ~/robot_vla_ws/install/setup.bash" >> ~/.bashrc

# ⑥ 看一眼显卡
nvidia-smi
```

**第 ⑥ 步的结果判断**：

- 显示出一块 **16GB 显卡**的表格 → ✅ 驱动已装，直接进入第 1 章
- 提示 `command not found` → 装驱动，装完重启：

```bash
sudo ubuntu-drivers autoinstall
sudo reboot
```

重启后重新登录（重走 0.2），再敲 `nvidia-smi` 确认。

> 顺带说一句：**不用单独装 CUDA Toolkit**。PyTorch 的安装包自带 CUDA 运行时，只要驱动在就够。这一步能省你半小时。

### 0.4 建 Git 仓库（现在就养成备份习惯）

```bash
cd ~/robot_vla_ws
git init
cat > .gitignore <<'EOF'
src/ros2_rm_robot/
build/
install/
log/
data/
models/
__pycache__/
*.pyc
EOF
git add .gitignore && git commit -m "init: 建立工作区骨架"
```

然后去 GitHub 或 Gitee 建一个**私有（private）**仓库，把地址记下来（后面会用到 `git remote add origin <地址>`）。

> **private 是免费的**：GitHub 和 Gitee 都免费提供无限私有仓库，不存在「要花钱」的问题。
> **不想建远端也行**：Git 本地就能用（`git init` 已经做了）。如果暂时不想折腾托管，可以定期把工作区打包拷回 Mac：
> `tar czf ~/ws_backup.tar.gz ~/robot_vla_ws` 再 `scp` 回来。
> 但远端仓库更省心——到期那天一次 `git push` 就全部安全了。

> 为什么现在就建？因为云服务器到期会销毁，Git 是你的「保险箱」。**从今天起，改一次代码就 commit 一次。**

### 0.4.1 能不能用 public 仓库？

能，但**不建议**，三个真实风险：

| 风险 | 后果 |
|------|------|
| 误提交密码 / 密钥 / 服务器 IP | GitHub 上有自动爬虫，几分钟内就被扫到并用来入侵你的服务器 |
| 示教数据、图像外泄 | 涉及项目或隐私信息 |
| 学业 / 论文 / 竞赛 | 提前公开可能被导师或评审认为不合适 |

> ⚠️ 最关键的一条：**密码一旦 push 上去，删文件也没用**——它会永远留在 git 历史里，只能去改密码 / 换密钥。

**折中做法**：开发阶段用 private；等项目成型、论文或答辩结束后，再把不含敏感信息的部分整理成 public 开源（对写简历、展示反而有好处）。

### 0.4.2 如果一定要用 public，务必做到

- [ ] 所有密码、密钥、Token 只放环境变量或 `~/.bashrc`，**绝不写进任何文件**
- [ ] 服务器 IP **不要**写进 README（用 `<你的服务器IP>` 占位）
- [ ] 提交前逐个文件看一遍：`git diff --cached`
- [ ] 大文件（模型、数据集）确认在 `.gitignore` 里

### 0.5 （以后再说）Mac 端要装的软件

等你需要更舒服地干活时再装，现在不用管：

| 软件 | 干什么 | 什么时候需要 |
|------|-------|-------------|
| **VS Code** + Remote-SSH 扩展 | 在 Mac 上舒服地写云端代码 | 开始写 Python 包时（P2） |
| **Foxglove Studio** | 看 3D 模型、相机图像、TF 树 | 想看机器人画面时（P0 验收） |
| XQuartz（兜底） | 把云端 RViz 窗口投到 Mac | Foxglove 在 Foxy 上装不上时 |

## 1. 先理清边界：哪些能在云端做，哪些必须等硬件

这是「乱」的根源，先把边界钉死。

| 阶段 | 云端 HAI 能做吗 | 需要什么 | 卡点 |
|------|---------------|---------|------|
| **P0 环境搭建** | ✅ 完整可做 | 只要服务器 | 无 |
| **P1 模型验证** | ✅ 完整可做 | URDF + 可视化 | 无 |
| **P2 基础控制** | ✅ 完整可做 | MoveIt2 + Gazebo | 无 |
| **P3 PID 控制** | ✅ 完整可做 | Gazebo 仿真 | 无 |
| **P4 视觉与手眼标定** | ⚠️ 半可做 | 代码 + **Gazebo 虚拟相机** | 真实相机标定需硬件 |
| **P5 OpenPI + vla_bridge** | ✅ 完整可做 | GPU（16GB 够推理） | 显存微调偏紧 |
| **P6 数据采集 + 微调** | ⚠️ 半可做 | 微调脚本 + 公开/仿真数据 | 真实拖动示教需真机 |
| P7–P8 真机 | ❌ 做不了 | 本地 Linux 主机 + 机械臂 | 云端连不到机械臂 |

**结论**：P0–P3、P5 这五个阶段在云端能一口气做完；P4、P6 只能把「代码和脚本」做好，等硬件到位再补真实数据。

## 2. 可移植性设计（先立规矩，再做任何事）

### 2.1 三样「能带走」的资产

| 资产 | 放哪 | 怎么带走 |
|------|------|---------|
| **① 代码 + 配置** | `~/robot_vla_ws`（Git 仓库） | push 到私有仓库，新机器 `git clone` |
| **② 环境脚本** | `~/robot_vla_ws/env/` | 随代码走，新机器跑脚本重装 |
| **③ 数据与模型** | `~/data`、`~/models` | 太大不进 Git；下载脚本 + 到期前 scp/COS 备份 |

### 2.2 目录结构（照这个建）

```
~/robot_vla_ws/                  ← Git 仓库根目录
├── src/
│   ├── ros2_rm_robot/           ← 官方包（clone 来的，.gitignore 排除）
│   ├── arm_perception/          ← ① 视觉
│   ├── arm_handeye/             ← ② 手眼标定
│   ├── arm_calibration/         ← ③ 运动学标定
│   ├── arm_control/             ← ④ PID 控制
│   ├── vla_bridge/              ← ⑤ OpenPI ↔ ROS
│   ├── vla_data/                ← ⑥ 数据采集
│   └── arm_grasp/               ← ⑦ 抓取编排
├── env/                         ← 【可移植核心】
│   ├── setup_system.sh          ← 装 NVIDIA 驱动、ROS2、MoveIt2
│   ├── setup_vla.sh             ← 装 miniconda + OpenPI 环境
│   ├── environment.yml          ← Python 依赖锁版本
│   ├── download_models.sh       ← 模型权重下载（学术加速）
│   └── README.md                ← 新机器从零开始的操作步骤
└── README.md
```

### 2.3 三条铁律（违反就会「搬不走」）

1. **不往系统里散装东西**：所有 Python 包装进 conda 环境（`environment.yml` 锁版本），所有系统级安装写进 `setup_system.sh`。
2. **代码即文档**：改一次就 `git commit` 一次。到期那天 `git push` 就是备份。
3. **大文件不进 Git**：模型权重、数据集写进 `.gitignore`，用 `download_models.sh` 记录来源。

## 3. P0：环境搭建

**目标**：`ros2 launch rm_bringup rm_eco65_gazebo.launch.py` 能启动，能看到 ECO65 模型。

### 3.1 装 ROS2 Foxy + MoveIt2

官方包里自带安装脚本，用它最稳：

```bash
# 先 clone 官方包
cd ~/robot_vla_ws/src
git clone -b foxy https://github.com/RealManRobot/ros2_rm_robot.git

# 装 ROS2（脚本在官方包里，跑起来要十几分钟）
cd ~/robot_vla_ws/src/ros2_rm_robot/rm_install/scripts
sudo bash ros2_install.sh

# 装 MoveIt2
sudo bash moveit2_install.sh

# 装 rm_driver 依赖库
cd ~/robot_vla_ws/src/ros2_rm_robot/rm_driver/lib
sudo bash lib_install.sh
```

> 装完 **重开一次终端**（或 `source ~/.bashrc`），再验证：
> `ros2 --version` 应该输出 `foxy`

### 3.2 ⚠️ 做完立刻固化成脚本

把上面这些命令**原样写进 `env/setup_system.sh`**（用 `vim` 或 `nano`），以后换机器直接跑脚本：

```bash
vim ~/robot_vla_ws/env/setup_system.sh
```

### 3.3 编译

```bash
cd ~/robot_vla_ws
colcon build --packages-select rm_ros_interfaces
source ./install/setup.bash
colcon build
source ./install/setup.bash
```

> 每次开新终端都要 `source ~/robot_vla_ws/install/setup.bash`（0.3 节第⑤步已经写进 `.bashrc` 了，开新终端会自动执行）。

### 3.4 启动仿真

```bash
source ~/robot_vla_ws/install/setup.bash
ros2 launch rm_bringup rm_eco65_gazebo.launch.py
```

另开一个终端检查：

```bash
ros2 node list
ros2 topic list | grep joint_states
```

### 3.5 怎么看画面（云端没图形界面）

**推荐**：云端装 bridge，Mac 装 Foxglove Studio 看：

```bash
sudo apt install ros-foxy-foxglove-bridge
ros2 launch foxglove_bridge foxglove_bridge_launch.xml
```

Mac 上 Foxglove → 「打开连接」→ `ws://43.139.163.227:8765`

> Foxy 兼容性要先试；若装不上，兜底方案：Mac 装 XQuartz，`ssh -X ubuntu@IP` 后跑 `rviz2`（会卡，但能看）。
> **最省事的验收**：不看画面也行，只要 `ros2 node list` 有节点、`ros2 topic echo /joint_states` 有数据，就算 P0 通过。

## 4. P1：模型验证（URDF / TF / 关节方向 / 零位）

**目标**：确认仿真里的 ECO65 和真机对得上。

### 4.1 核对 TF 树

```bash
# view_frames 在部分环境不可用；用 tf2_echo 更直接（注意真实帧名！）
ros2 run tf2_ros tf2_echo baselink Link6
```

**真实链路（实测）**：`world → baselink → Link1 → Link2 → Link3 → Link4 → Link5 → Link6`

> ❗ 命名与手册完全不同：根帧 `baselink`、连杆 `Link1`~`Link6`、**无 tool0**（末端即 Link6）。
> 零位实测平移 `[−0.086, 0.021, 0.772]`，与 MDH 手算吻合（x = a₂ = −0.086，z ≈ 0.1625+0.26+0.24+0.11）。
> `tf2_echo base_link` 会报 "frame does not exist" —— 就是名字错了，用 `baselink`。

### 4.2 核对关节方向与零位

用 02 方案里的 **MDH 参数**和关节限位逐项核对（J1/J4/J5 ±3.106、J2 −3.106~2.356、J3 −2.792~2.53、J6 ±6.28）。

写 `src/arm_calibration/check_model.py`：输入关节角 → 输出末端位姿 → 与 MDH 手算结果比对。

### ✅ P1 验收

- [ ] TF 树完整：`baselink → Link1…Link6`，末端是 Link6（不是 tool0）
- [ ] 6 个关节转动方向与说明书一致
- [ ] FK 计算值与 MDH 手算一致（误差 < 1e-6）

### 📦 可移植动作

```bash
git add src/arm_calibration/ && git commit -m "P1: 模型校验脚本 + 关节方向核对"
git push
```

## 8. P5：OpenPI 部署 + vla_bridge（云端重头戏）

**目标**：模型能推理，ROS 能收发 `/vla/*` 四个话题。

### 8.1 ⚠️ 关键坑：Python 版本

OpenPI 需要 **Python 3.11+**，但 Ubuntu 20.04 系统 Python 是 3.8（ROS2 Foxy 也依赖它）。

**绝不能动系统 Python**，必须用独立 conda 环境：

```bash
# 装 miniconda
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
bash Miniconda3-latest-Linux-x86_64.sh -b -p $HOME/miniconda
$HOME/miniconda/bin/conda init bash
# 重开终端后
conda create -n openpi python=3.11 -y
conda activate openpi
```

### 8.2 装 PyTorch + OpenPI

```bash
conda activate openpi
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu118
python -c "import torch; print(torch.cuda.is_available())"   # 必须是 True

git clone https://github.com/Physical-Intelligence/openpi.git ~/openpi
cd ~/openpi && pip install -e .
```

> 把流程写进 `env/setup_vla.sh`，并导出锁定版本：
> `conda env export > ~/robot_vla_ws/env/environment.yml`

### 8.3 四个话题

| 话题 | 方向 | 内容 |
|------|------|------|
| `/vla/instruction` | → | 语言指令 |
| `/vla/image` | → | 相机图像 |
| `/vla/robot_state` | → | 关节角 + 末端位姿 + 夹爪 |
| `/vla/action` | ← | 位姿增量 + 夹爪 |

**先用「假推理进程」跑通全链路**（回显固定动作），确认收发正常再接真模型。

## 10. 换机器时：新机器重建流程

任何一台新的 Ubuntu 20.04（再租云、或买的本地小主机），照做：

```bash
# 1. 装系统依赖
git clone <你的仓库地址> ~/robot_vla_ws
cd ~/robot_vla_ws && bash env/setup_system.sh

# 2. 拉官方包 + 编译
cd ~/robot_vla_ws/src
git clone -b foxy https://github.com/RealManRobot/ros2_rm_robot.git
cd ~/robot_vla_ws
colcon build --packages-select rm_ros_interfaces && source install/setup.bash
colcon build && source install/setup.bash

# 3. 装 VLA 环境
bash env/setup_vla.sh
conda activate openpi

# 4. 下模型
bash env/download_models.sh

# 5. 验证
ros2 launch rm_bringup rm_eco65_gazebo.launch.py
```

**这套流程跑通 = 环境真的可移植。** 建议到期前用一台干净环境试一次。

## 12. 时间预期与常见坑

| 阶段 | 云端可做部分 | 大致耗时 |
|------|------------|---------|
| P0 | 完整 | 1–2 天 |
| P1 | 完整 | 1 天 |
| P2 | 完整 | 1–2 周 |
| P3 | 完整 | 1–2 周 |
| P4 | 代码部分 | 1 周（+硬件后补标定） |
| P5 | 完整 | 3–5 天 |
| P6 | 脚本部分 | 1 周（+真机后补数据） |

> 6 天只够「P0 + P5 打通」，这是正常的。剩下的等买了本地 Linux 小主机，用同样的脚本继续。

### 四个高频坑

1. **忘记 source**：新终端要 `source ~/robot_vla_ws/install/setup.bash`（已写进 `.bashrc`）。
2. **动系统 Python**：装 VLA 依赖时手滑用系统 pip，会污染 ROS2。**永远先 `conda activate openpi`**。
3. **大文件进 Git**：几十 GB 模型 push 会卡死，务必写进 `.gitignore`。
4. **忘了提交**：改完不 commit，到期就丢。**改一次提交一次**。
