## 一句话结论（先看这个）

> 📌 **最终决策（用户 2026-10-28 拍板）：选 D435i** —— 要通用性 + RGB 1080p 利于 π0。
> 安装方案见 `24_RealSense_D435i_真机安装方案.md`。
> 本节保留纯技术对比供日后复盘。

**纯技术角度看，D405 的近距精度更高，D455 直接排除。**

理由不是"精度越高越好"，而是**量程必须覆盖你实际的工作距离**：
D455 最小工作距离 0.4 m，而我们实测的观测距离是 **0.43 m**——刚好卡在盲区边缘，太危险。

## 一、为什么型号不定会卡住整条链

```
相机型号  ──决定──▶  librealsense SDK 版本
                          │
                          ├──决定──▶ 相机固件版本（固件与 SDK 必须匹配）
                          │
                          └──决定──▶ realsense-ros Wrapper 版本
                                          │
                                          └──必须兼容──▶ ROS2 Foxy（EOL，支持面在收窄）
```

任何一环对不上，表现就是：`rs-enumerate-devices` 看不到设备、或能出流但深度全 0、或编译不过。
所以**型号是所有版本号的上游**，必须先定。

## 三、用本项目的真实距离去匹配（这是关键）

仿真里实测的两个关键距离：

| 环节 | 相机位置 | 目标 | **实际距离** |
|---|---|---|---|
| 观测姿势（远看） | (0.20, 0.25, 0.30) | 方块 (0.40, 0, 0.02) | **≈ 0.43 m** |
| 抓取姿势（近看） | 下降到位后 | 方块 | **≈ 0.30 m** |

把这三个型号的量程画上去：

```
       0.07        0.2    0.3   0.43        1.0              3.0        6.0 m
        |-----------|------|------|----------|----------------|----------|
D405    [████████████████████████████████████]                        (7cm–1m)
D435i         [████████████████████████████████████████████]          (0.2–3m)
D455                       [████████████████████████████████████]     (0.4–6m)
                            ↑ 0.43m 观测距离，卡在 D455 起点，太危险
```

**逐条判断**：

| 型号 | 覆盖 0.30m？ | 覆盖 0.43m？ | 余量评价 |
|---|---|---|---|
| D405 | ✅（7cm 起，余量极大） | ✅（上限 1m，余量 2.3 倍） | **最好** |
| D435i | ✅（0.2m 起） | ✅ | 良好 |
| D455 | ❌ **0.4m 起，0.43m 几乎贴边** | ⚠️ 贴边 | **不可用** |

## 四、推荐与取舍

### 首选：D405

- **近距精度最高**：D405 是专为近距离设计的短基线型号，在 0.3~0.5 m 这个区间的深度精度
  明显高于 D435i（后者要兼顾 3m 量程，近距精度被稀释）
- **体积小、重量轻**（42×42×23 mm）：腕部负载和转动惯量都更小，对机械臂轨迹精度友好
- **全局快门**：机械臂快速运动不会拖影

代价：量程上限 1 m，且无 IMU（本项目本来就打算关 IMU，无所谓）。

### 稳妥备选：D435i

- 量程 0.2–3 m，通用性最好，将来要扩展场景（远距导航、更大工作台）不用换相机
- RGB 1080p，对 π0 的视觉输入更友好（D405 只有 720p）
- 社区资料最多，出问题最好查

### 明确排除：D455

最小工作距离 0.4 m，而我们的观测距离是 0.43 m —— **一旦位姿稍有偏差就进盲区，深度直接消失**。
这类"参数刚好够、实际没余量"的选择是最容易踩的坑。

> ⚠️ **选型原则（值得记住）**：不要只看"最远能看多远"，
> **腕装相机最先要看的是最近能看多近**——因为相机是跟着手靠近物体的。

## 五、版本钉死原则（型号定了再填具体号）

型号确定后按这个顺序钉，并在每一步用命令验证：

```bash
# 1) 选 librealsense 版本：查官方 release notes 里"支持该型号最早固件"的条目
#    原则：不要追最新（新版本对 Foxy 支持在弱化），选该型号发布后 3~6 个月内的稳定版

# 2) Ubuntu 20.04 一律走 RSUSB 用户态后端，不碰内核 uvcvideo（保护机械臂环境）
cmake .. -DFORCE_RSUSB_BACKEND=ON -DCMAKE_BUILD_TYPE=Release

# 3) realsense-ros 用 ros2-master 分支（ros2-development / ros2-legacy 已废弃）

# 4) 每一步都要验证（不要"装完以为好了"）
rs-enumerate-devices          # 能看到设备 + 固件版本
ros2 topic hz /camera/color/image_raw
timeout 5 ros2 topic echo /camera/depth/image_rect_raw   # 深度值不能全 0
```

> 这条"每一步都要验证"是针对本项目最大的教训写的：
> 仿真里我们有整整六天以为"环境只支持 position 接口"，实际上是被僵尸进程骗了——
> **没验证过的结论不能当成前提。**

## 六、真机准备清单（相机之外的部分）

### 6.1 夹爪控制律（MS42DC 只有位置模式）

仿真用的是"恒定力矩"，真机要用**过冲 + 堵转电流**等效：

```
真机做法：目标位置 = 物体表面再往里 1~2 mm
         → 电机顶住物体转不动 → 堵转 → 由电流上限维持夹持力
         → 物理上等价于仿真里的"恒定力矩顶住"
```

待实测量：
- 夹爪闭合到不同开度时的堵转电流（用于反推夹持力）
- 4cm 方块在 μ≈1.5 下需要的电流下限（理论 0.2 N/侧，实测校正）

### 6.2 手眼标定（仿真里是已知精确外参，真机必须实标）

- 标定板固定在桌面，机械臂带相机走 10~15 个位姿
- 求 `X = T_flange←camera`（眼在手）
- 已有求解器：`recovery/` 下的 `handeye_calib.py`（支持 `--mode eye_in_hand`）
- **TF 要发 `flange → d435i_link`，不能发到 `optical_frame`**（会和 realsense 自己那条边形成双父冲突）

### 6.3 π0 的第三人称视角缺口

π0 需要 `base_0_rgb`（场景视角），而我们只有腕装相机 → **建议补一台便宜的固定 USB RGB 摄像头**（不需要深度）。
过渡期可把腕部图塞进 `base_0_rgb` 槽位做接口冒烟测试，但别指望效果。

### 6.4 上电检查脚本（等真机能碰时直接跑）

待产出：一个 `check_real_robot.sh`，一次性盘点
ROS 版本 / 串口设备（夹爪 `/dev/motor_serial`，vid `1a86` pid `55d4`）/ 相机设备 / 机械臂连通性 / 磁盘。

### 6.5 安全（真机必须有，仿真没有）

- 力矩/碰撞保护阈值
- 急停回路
- 首次运行必须低速、单步、有人守
