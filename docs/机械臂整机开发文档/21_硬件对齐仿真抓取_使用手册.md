# 21｜硬件对齐版仿真抓取闭环 — 使用手册

> 适用对象：睿尔曼 ECO65-6FB + 轮趣 MS42DC 二指夹爪 + 腕部 RealSense 规格深度相机
> 目标物：边长 4cm 的绿色方块
> 环境：云服务器 `ubuntu@你的服务器IP`（Ubuntu 20.04 + ROS2 Foxy + Gazebo 11）
> 编写时间：2026-10-28　配套阅读：`22_仿真抓取问题汇总与面试资料.md`

---

## 一句话：这份手册解决什么

告诉你**怎么一键把"看见方块 → 走过去 → 夹住 → 抬起来"这条链跑起来**，以及跑挂了去哪儿查。

和旧版最大的不同：**夹爪改成了力矩（effort）驱动**，不再是位置驱动。
这不是"换个接口"的小事，而是决定能不能夹住的根本原因，详见 22 号文档。

**一句话理解每层**：相机告诉你在哪 → 数学算出怎么走 → 控制器发出命令 → 物理引擎决定夹不夹得住。

## 一、最快跑法（三条命令）

```bash
# 1) 登录云服务器
ssh ubuntu@你的服务器IP

# 2) 一键跑完整闭环（含清场、启动仿真、生成方块、执行抓取）
setsid nohup bash /tmp/run_eff.sh > /tmp/run_eff_outer.log 2>&1 < /dev/null &

# 3) 看结果（约 4~5 分钟跑完）
tail -20 /tmp/eff_run.log
```

**成功的样子**：

```
===== 结论 =====
  起始:   [ 0.4    -0.      0.0192]
  下降后: [ 0.4    -0.      0.0192]
  夹持后: [0.4003 0.0005 0.0183]
  抬升后: [0.4006 0.0008 0.117 ]
  dz = +0.0978 m -> ★ 夹起来了！
  NaN: 无
```

**失败的样子**：`dz = -0.0000 m -> 没夹起来`。
失败时不要立刻改代码，先看第 5 节的故障速查。

> ⚠️ **必须用 `setsid nohup ... &` 后台跑**。直接在前台跑，ssh 一断子进程就被带走，
> 而且会留下"半死不活"的进程污染下一次运行（这是本项目最大的坑，见 22 号文档）。

## 二、文件地图（改东西前先知道改哪个）

### 2.1 云服务器的脚本（都在 `/tmp`）

| 文件 | 作用 | 什么时候用 |
|---|---|---|
| `run_eff.sh` | **一键跑全流程**：清场 → 起仿真 → 生成方块 → 跑测试 | 每次验证 |
| `eff_test.py` | **主力测试脚本**：感知→规划→下降→夹持→抬升 | 改逻辑时 |
| `cleanup.sh` | **彻底清场**（杀 gzserver / robot_state_publisher 等） | 每次跑之前 |
| `build_plugin.sh` | 重新编译 `gazebo_grasp_fix` 插件 | 改插件源码后 |
| `eff_check.sh` | 只起仿真并打印硬件接口/控制器状态 | 排查接口问题时 |
| `tau_probe.py` | 力矩探针：发几个固定力矩看手指动不动 | 验证 effort 是否生效 |

### 2.2 配置与模型

| 路径（云） | 作用 |
|---|---|
| `~/robot_vla_ws/src/arm_perception/urdf/eco65_camera.urdf.xacro` | **夹爪几何、手指惯量、grasp_fix 插件参数**（最常改） |
| `~/robot_vla_ws/src/ros2_rm_robot/rm_gazebo/config/gazebo_eco65_description.urdf.xacro` | ros2_control 接口声明（手指 = `effort`） |
| `install/rm_eco65_config/.../ros2_controllers.yaml` | 控制器类型（手指 = `effort_controllers/JointGroupEffortController`） |
| `/tmp/grasp.world` | **调好的物理世界**（步长 0.0002s、ODE iters 300）— 丢了会很不稳定 |
| `~/robot_vla_ws/models/target_box/model.sdf` | 目标方块：4cm 立方体、60g |
| `/tmp/eco65_6fb.urdf` | IK 用的运动学模型（基系 baselink → Link6） |
| `~/robot_vla_ws/src/arm_perception/launch/camera_sim_min.launch.py` | 启动入口 |
| `~/gazebo-pkgs/`、`~/gazebo_plugins/libgazebo_grasp_fix.so` | 抓取插件源码与编译产物 |

> 💡 `install/` 下的 xacro 和 yaml 大多是 **`src/` 的软链接**，改 `src` 就够了。
> 但 `$(find rm_gazebo)` 这类路径解析到的是 **install**，所以判断"实际生效的是哪份文件"时，
> 用 `ls -l` 看是不是软链最靠谱。

### 2.3 日志在哪

| 路径 | 内容 |
|---|---|
| `/tmp/eff_run.log` | **主日志**：每个阶段的角度、开口、方块坐标 |
| `/tmp/graspfix_loaded.txt` | **插件内部标记**（Load / 接触 / 判定 / 吸附）— 排障利器 |
| `/tmp/eff_hw2.txt` | 硬件接口与控制器状态 |
| `/tmp/sim_eff.log` | Gazebo + ros2_control 启动日志 |

## 三、关键参数（想调手感就改这些）

都在 `/tmp/eff_test.py` 顶部：

| 参数 | 现值 | 含义 | 调大的后果 |
|---|---|---|---|
| `OPEN_T` | 0.20 rad | 张开目标角（开口 58mm） | 太大撞限位 |
| `PRE_T` | 0.04 rad | 预夹角（开口 42mm，单边留 1mm） | 太接近会提前撞到方块 |
| `TAU_MOVE` | 0.020 N·m | 移动手指的恒定力矩 | 动得快，但可能撞飞方块 |
| `TAU_GRIP` | 0.030 N·m | **夹持力矩**（指尖约 0.6N/侧） | 夹得紧，但可能压爆接触 |
| `TAU_MAX` | 0.060 N·m | 力矩硬上限 | 安全兜底 |
| `KD` | 0.030 | 阻尼项，限速 ≈ TAU_MOVE/KD ≈ 0.67 rad/s | 越小越快越容易振 |
| `LIFT` | 0.10 m | 抬升高度 | — |

**夹得住的物理账**（换成别的目标物时按这个算）：
- 方块重力 `0.06 kg × 9.8 = 0.59 N`
- 摩擦系数 μ ≈ 1.5，两侧对捏需要的最小正压力：`0.59 / (2 × 1.5) ≈ 0.20 N`
- 当前每侧 0.6 N → **约 3 倍余量**，够但不过分

## 四、验收标准

| 指标 | 判据 | 当前最好成绩 |
|---|---|---|
| **主指标** | `dz > 0.02 m` | **+0.0978 m** ✅ |
| 感知精度 | 感知中心 vs 真值 < 3mm | ~1mm ✅ |
| 下降不扰动物体 | 下降后方块水平位移 < 1cm | 0.8mm ✅ |
| 抬升途中不掉 | 全程方块 z 单调上升 | ✅ |
| 数值稳定 | 无 NaN | ✅ |
| **可复现** | 连跑 3 次都成功 | ❌ **尚未达成** |

## 五、故障速查

| 现象 | 先看哪儿 | 大概率原因 / 处理 |
|---|---|---|
| `arm action 未就绪` | `/tmp/eff_hw2.txt` | 启动竞态。等控制器 `active` 再跑（脚本已改成轮询） |
| `ros2: command not found` | — | 忘了 `source /opt/ros/foxy/setup.bash` + `source ~/robot_vla_ws/install/setup.bash` |
| 手指完全不动 | `/tmp/eff_hw2.txt` | 没有 `finger_left_joint/effort [claimed]` → 跑 `tau_probe.py` 单独验证 |
| 手指剧烈抖动/角度乱跳 | `/tmp/eff_run.log` | 惯量太小导致数值振荡。检查 xacro 里 `izz` 是否为 `1.0e-3` |
| 改了 URDF 却没生效 | `cat /tmp/graspfix_loaded.txt` | **僵尸 robot_state_publisher 抢发旧 URDF**。跑 `cleanup.sh` |
| 插件"像没加载" | `/tmp/graspfix_loaded.txt` | 别信控制台日志（会整体丢失）。看标记文件，或 `gz topic -l \| grep grasp_events` |
| 方块被撞飞 | 日志里下降段 | 路径不是笛卡尔直线，或夹爪滚转角没对齐（见 22 号文档第 3 条） |
| 夹住了但抬不起 | `graspfix_loaded.txt` 里 `links=` | 多数时刻 `links=1` → 只有一根手指碰到。查 `disable_collisions_on_attach` |

## 六、和真机的对应关系（哪些会带过去）

| 仿真里的东西 | 真机上的对应 | 是否可直接迁移 |
|---|---|---|
| 腕部相机点云定位 | RealSense 点云定位 | ✅ 算法一致，只换话题名和标定 |
| DLS-IK + 滚转对齐 | 同 | ✅ 完全一样 |
| 笛卡尔直线下降/抬升 | 同 | ✅ 完全一样 |
| **effort 恒力矩夹持** | MS42DC **电流限制夹持** | ⚠️ 真机是**位置模式**，需用"目标位置略过物体表面 + 堵转电流"等效实现 |
| 手指等效惯量 `izz=1.0e-3` | 电机+减速器折算惯量 | ✅ 建模方法通用 |
| `gazebo_grasp_fix` 吸附 | **真机不需要**（真实摩擦足够） | ❌ 纯仿真补丁 |
| 几何判据（两指接触=夹住） | 真机用电流/力矩反馈判断 | ⚠️ 判据来源不同，逻辑可复用 |

> **最重要的一条**：真机 MS42DC 只有位置模式。要复现仿真里的"恒力矩"效果，
> 做法是**把目标位置设得比物体表面再深一点点**，让电机堵转、靠电流上限维持夹持力——
> 这和仿真里"恒定力矩顶住"在物理上是同一件事。

## 七、日常操作小抄

```bash
# 登录并准备好环境（每次新开终端都要）
ssh ubuntu@你的服务器IP
source /opt/ros/foxy/setup.bash
source ~/robot_vla_ws/install/setup.bash

# 手动查方块位置
gz model -m target_box -p

# 查控制器 / 接口
ros2 control list_controllers
ros2 control list_hardware_interfaces

# 确认抓取插件真的在工作
gz topic -l | grep grasp_events          # 应有 /gazebo/grasp_world/grasp_events
cat /tmp/graspfix_loaded.txt             # 应有 LOAD_START / INIT_OK / ATTACH

# 重新编译插件（改了 ~/gazebo-pkgs 里源码之后）
bash /tmp/build_plugin.sh

# 彻底清场（跑下一轮之前必做）
bash /tmp/cleanup.sh
```
